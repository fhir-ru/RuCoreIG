# Core_EpisodeOfCare — Профиль эпизода лечения

## Принятые решения по профилированию

| Бизнес-требование | Атрибут | Решение по профилированию |
|-------------------|---------|---------------------------|
| Описание пациента должно соответствовать требованиям РФ | patient | Должен быть представлен профилем Core_Patient |
| Описание организации, ответственной за эпизод помощи, должно соответствовать требованиям РФ | managingOrganization | Должен быть представлен профилем Core_Organization |

## Описание профиля

Профиль Core_EpisodeOfCare расширяет стандартный ресурс EpisodeOfCare для поддержки российских требований:
- Пациент должен быть представлен профилем Core_Patient
- Организация, ответственная за эпизод помощи, должна быть представлена профилем Core_Organization

## Моделирование амбулаторной помощи

**Проект для обсуждения на встрече сообщества. Модель ещё не утверждена; новые ограничения профилей не вводятся.**

Учётная и клиническая группировки независимы:

- **Амбулаторная карта** — агрегирующий `Encounter`, представляющий учётный контекст обслуживания пациента в организации, а не содержимое карты как документа. Посещение — отдельный `Encounter`, связанный с картой через `partOf`.
- **Случай поликлинического обслуживания (СПО)** в этой модели — `EpisodeOfCare`: ведение пациента по определённой клинической проблеме под ответственностью организации. Посещения связаны с ним через `episodeOfCare` (`0..*`); одно посещение может относиться к нескольким СПО.
- Карта и СПО имеют собственные периоды и статусы. Завершение посещения не означает закрытие карты или СПО. При участии нескольких организаций каждая ведёт свой `EpisodeOfCare`, отражающий её ответственность.

![Два посещения относятся к одной амбулаторной карте через partOf. Первое посещение входит в СПО по диабету, второе — в СПО по диабету и по боли в спине через episodeOfCare.](ambulatory-care-model.svg)

Пример: оба посещения относятся к карте № 5499-16. На первом обсуждается диабет, на втором — диабет и боль в спине. Для этих проблем ведутся два СПО одной организации.

| Посещение | Учётная связь `partOf` | Клинические связи `episodeOfCare` |
|---|---|---|
| Посещение 1 | Карта № 5499-16 | СПО «Диабет» |
| Посещение 2 | Карта № 5499-16 | СПО «Диабет», СПО «Боль в спине» |

СПО не является обязательным промежуточным уровнем между картой и посещением. Наличие карты или СПО не требуется для каждого посещения. При передаче связи допустима ссылка на экземпляр либо логическая ссылка через `Reference.identifier`, если известен только идентификатор.

Основания: FHIR допускает [агрегацию Encounter через partOf](https://hl7.org/fhir/R5/encounter.html#scope), [несколько episodeOfCare у одного Encounter](https://hl7.org/fhir/R5/encounter-definitions.html#Encounter.episodeOfCare) и описывает [ответственность организаций в EpisodeOfCare](https://hl7.org/fhir/R5/episodeofcare.html). Представление амбулаторной карты агрегирующим Encounter — предлагаемое соглашение RuCore.

На утверждение выносятся смысл СПО и две независимые связи. Кодирование уровня Encounter и типа карты, а также соответствие идентификаторов СЭМД этим сущностям требуют отдельного решения.

См. также [описание модели в Core_Encounter](StructureDefinition-core-encounter.html).

### FSH-код профиля

```fsh
Profile: Core_EpisodeOfCare
Parent: EpisodeOfCare
Id: core-episodeofcare
Title: "Core EpisodeOfCare (Эпизод лечения)"
Description: "Базовый профиль эпизода лечения для российских FHIR-реализаций"

* patient only Reference(Core_Patient)
* managingOrganization only Reference(Core_Organization)
```
