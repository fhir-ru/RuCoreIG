# Core_Bundle — Профиль пакета ресурсов

## Принятые решения по профилированию

| Бизнес-требование | Атрибут | Решение по профилированию |
|-------------------|---------|---------------------------|
| Необходимо нормировать представление идентификатора конкретного экземпляра документа в МИС | identifier | При типе `mis-document` условный invariant проверяет обязательность `system` и `value` и типовой узел `.51`; идентификатор иного типа остается допустимым |

## Описание профиля

`Core_Bundle` сохраняет все типы и сценарии применения базового `Bundle`. Профиль не фиксирует `Bundle.type` и нормирует вариант `identifier` типа `mis-document` с типовым узлом `.51`.

У `Bundle.identifier` кардинальность `0..1`, а FHIR разрешает нарезку только для повторяющихся элементов либо элементов выбора (`[x]`). Поэтому формально описать открытый срез здесь невозможно. Вместо него применено условное ограничение: если `Identifier.type` содержит код `mis-document`, должны присутствовать `system` и `value`, а `system` должен завершаться типовым узлом `.51`. При другом типе это ограничение не применяется, то есть идентификатор остается открытым для иных вариантов.

### Сопоставление идентификаторов и версий документа

| CDA | FHIR R5 | Смысл |
|-----|---------|-------|
| `ClinicalDocument.id` | `Bundle.identifier` типа `mis-document` с узлом `.51` | Уникальный идентификатор конкретного экземпляра документа |
| `ClinicalDocument.setId` | `Composition.identifier[misDocumentSet]` с узлом `.50` | Постоянный идентификатор набора версий |
| `ClinicalDocument.versionNumber` | `Composition.version` | Номер или обозначение версии |

Идентификатор `.51` не следует помещать в `Composition.identifier`: этот элемент имеет version-independent семантику. `Composition.version` используется без дополнительных ограничений RuCore, поскольку российских особенностей его представления не установлено.

Для document Bundle базовый FHIR R5 требует наличие `Bundle.identifier.system` и `Bundle.identifier.value`. Специализированное руководство может дополнительно установить `identifier 1..1` и зафиксировать его тип, если в его сценарии требуется именно идентификатор СЭМД.
