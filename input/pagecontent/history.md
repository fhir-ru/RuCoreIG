# История изменений

На данной странице приводятся сведения о версиях Implementation Guide RuCore и о ключевых изменениях между версиями.

## Версия 0.7.0

Статус: draft

Ключевые изменения:

* Национальные терминологические привязки в базовых профилях RuCore ослаблены с `required` до `extensible`, чтобы использование российских справочников оставалось обязательным по смыслу, но отсутствие нужного кода не блокировало реализацию.
* Нормализованы канонические URI identifier system для `snils`, `identity-document` и `oms` во всех затронутых профилях.
* Добавлены `NamingSystem` для `identity-document`, `okpo` и `frmo`.
* Примеры ресурсов приведены к каноническим identifier system RuCore для основных идентификаторов, чтобы опубликованные образцы демонстрировали эталонную модель RuCore.
* Из профилей удалены явные тавтологии базовой FHIR-спецификации, которые не добавляли собственного контракта RuCore, включая повторные bindings для `Procedure.status` и `RelatedPerson.telecom.system`.
* Для идентификатора ФРМО введен отдельный URI identifier system `https://fhir.ru/ig/core/systems/frmo` вместо использования URI `CodeSystem` в `Organization.identifier.system`.

## Версия 0.6.0

Статус: draft

Ключевые изменения:

* Исправлены слишком узкие ограничения `Reference(... only ...)` в базовых процессных профилях RuCore с учетом базовой спецификации FHIR R5.
* В `Core_ServiceRequest`, `Core_DiagnosticReport`, `Core_Encounter`, `Core_Procedure` и `Core_CareTeam` возвращены все допустимые типы ссылок из R5, при этом для типов ресурсов, имеющих RuCore-профили, сохранено требование использовать именно профили RuCore.
* В `Core_Composition` снято некорректное сужение `subject`, чтобы не терять семантику `Reference(Any)` из R5, а для `author` и `attester.party` восстановлены все допустимые типы ссылок с использованием RuCore-профилей там, где они существуют.
* Обновлены связанные intro-страницы профилей, чтобы текстовая документация соответствовала новым ограничениям ссылок.

## Версия 0.5.0

Статус: draft

Ключевые изменения:

* Для `RelatedPerson.relationship` удалены локальный `CodeSystem` RuCore и связанные `ConceptMap`.
* Набор значений `relatedperson-relationship` переведен на использование кодов справочников НСИ МЗ РФ `1.2.643.5.1.13.13.99.2.14` и `1.2.643.5.1.13.13.11.1021`.
* Обновлены профиль `Core_RelatedPerson`, примеры и раздел 13 главы 5 ГОСТ-представления.
* Изменение внесено потому, что ведение отдельного справочника отношений не относится к ответственности группы разработчиков RuCore; практичнее опираться на существующие справочники НСИ МЗ РФ.

## Версия 0.4.2

Статус: draft

Ключевые изменения:

* На intro-странице `CodeSystem` `core-relatedperson-relationship` рядом с OID словарей НСИ МЗ РФ добавлены их наименования.
* В описаниях `ConceptMap` добавлены ссылки на соответствующие внешние справочники HL7 и НСИ МЗ РФ.
* В `ConceptMap` заполнены scope-поля, чтобы на опубликованных страницах не отображалась фраза `Mapping from (not specified) to (not specified)`.

## Версия 0.4.1

Статус: draft

Ключевые изменения:

* Для `CodeSystem` `core-relatedperson-relationship` добавлена intro-страница с навигационными ссылками на связанные `ConceptMap`.
* Улучшена видимость маппингов между каноническими отношениями RuCore, кодами HL7 и словарями НСИ МЗ РФ в опубликованном IG.

## Версия 0.4.0

Статус: draft

Ключевые изменения:

* Переработана терминологическая модель для `RelatedPerson.relationship`.
* Локальный `CodeSystem` `core-relatedperson-relationship` заменен на канонический набор понятий RuCore с собственными кодами.
* Добавлены явные `ConceptMap` для соответствия понятий RuCore кодам HL7 и словарям НСИ МЗ РФ `1.2.643.5.1.13.13.99.2.14`, `1.2.643.5.1.13.13.11.1021`, `1.2.643.5.1.13.13.99.2.240`.
* Обновлены `ValueSet`, профиль `Core_RelatedPerson` и примеры использования `RelatedPerson` в соответствии с новой канонической системой кодирования.
* В главе 5 ГОСТ-представления профилей добавлен сводный перечень используемых наборов значений с указанием опорных справочников и правил отбора элементов.

## Версия 0.3.0

Статус: draft

Ключевые изменения:

* Пересмотрена интерпретация профиля `Core_Address`.
* `Core_Address` рассматривается как профиль адреса на территории Российской Федерации, а не как универсальный национальный профиль любого адреса.
* Для адресов объектов, расположенных на территории Российской Федерации, применяется профиль `Core_Address`.
* Для адресов вне территории Российской Федерации применяется базовый тип данных `Address`.
* В профилях ресурсов внесена корректировка ограничений и пояснений, связанных с использованием `Core_Address`.

## Версия 0.2.0

Статус: baseline

Ключевые изменения:

* Сформирован исходный набор базовых профилей RuCore на основе FHIR R5.
* Определены базовые ресурсы, расширения, наборы значений и примеры для российского контекста использования.
