# История изменений

На данной странице приводятся сведения о версиях Implementation Guide RuCore и о ключевых изменениях между версиями.

## Версия 0.13.0

Статус: draft

Ключевые изменения:

* В `NamingSystem` ИНН добавлен машинно-обрабатываемый тип `http://terminology.hl7.org/CodeSystem/v2-0203#TAX` и явно описано семантическое соответствие: ИНН является конкретной российской системой налоговой идентификации, а `TAX` — общей категорией назначения идентификатора HL7.
* Уточнено, что в экземплярах ресурсов URI `https://fhir.ru/ig/core/systems/inn` передается в `Identifier.system`, а код `TAX` — в `Identifier.type`; эти значения выполняют разные функции и не заменяют друг друга.
* Соответствующие пояснения синхронизированы с текстом проекта ГОСТ.

## Версия 0.12.0

Статус: draft

Ключевые изменения:

* В `Core_Coverage` добавлен общий слой `identifier[coverageDocument]` для документов-оснований оплаты медицинских услуг с привязкой к справочнику НСИ МЗ РФ `Документы-основания для оплаты`.
* Специализированный срез `identifier[omsPolicy]` для полиса ОМС сохранен; в описании профиля отдельно отмечено, что при текущей модели номер полиса ОМС приходится указывать и как общий документ-основание оплаты, и как специализированный идентификатор ОМС.
* Для `address-type` и `region-rf` в `NamingSystem` исправлены канонические URI `CodeSystem`: `http` заменен на `https`.

## Версия 0.11.2

Статус: draft

Ключевые изменения:

* В разделе проекта ГОСТ обновлен маркер синхронизации с актуальной CI-версией RuCore.
* В текст ГОСТ добавлены alias-идентификаторы `NamingSystem` для `snils`, `ogrn` и `inn`: соответствующие OID и формы `urn:oid:...`.

## Версия 0.11.1

Статус: draft

Ключевые изменения:

* В человекочитаемых описаниях профилей `Core_Coverage` и `Core_Patient`, а также в ГОСТ-представлении уточнены формулировки о кодировании вида полиса ОМС через срез `omsType`.
* Термины приведены к более точному виду: вместо формулировок о «виде идентификатора» и «коде полиса» используется описание «вида полиса ОМС».

## Версия 0.11.0

Статус: draft

Ключевые изменения:

* В `NamingSystem` для `snils`, `ogrn` и `inn` добавлены распространенные в российских интеграциях внешние идентификаторы: OID и соответствующая URI-форма `urn:oid:...`.
* Канонические URI RuCore для этих identifier system сохранены как `preferred`.
* Из базовых профилей и примеров удалены вводившие в заблуждение HL7 identifier type коды для СНИЛС, полиса ОМС, документа, удостоверяющего личность, и кода медицинской услуги; сохранен только `TAX` для ИНН.
* Для полиса ОМС в `Core_Patient` и `Core_Coverage` оставлено только национальное кодирование вида полиса через справочник НСИ МЗ РФ.

## Версия 0.10.0

Статус: draft

Ключевые изменения:

* Справочник видов полиса ОМС переведен с вспомогательного справочника НСИ МЗ РФ `1.2.643.5.1.13.13.99.2.245` на основной справочник `1.2.643.5.1.13.13.11.1035` «Виды полиса ОМС».
* Справочник источников оплаты переведен с `1.2.643.5.1.13.2.1.1.153` на основной справочник НСИ МЗ РФ `1.2.643.5.1.13.13.11.1039` «Источники оплаты медицинской помощи».
* Обновлены связанные `CodeSystem`, `NamingSystem`, `ValueSet`, профили, примеры и ГОСТ-представление.

## Версия 0.9.1

Статус: draft

Ключевые изменения:

* В описаниях `CodeSystem` для справочников НСИ МЗ РФ исправлены человекочитаемые ссылки: они ведут на соответствующие страницы НСИ, а не на канонические URL RuCore.
* Канонические URL терминологических артефактов RuCore сохранены без изменений; связь с внешними справочниками НСИ по-прежнему фиксируется через `NamingSystem`.

## Версия 0.9.0

Статус: draft

Ключевые изменения:

* Для `Core_Patient.identifier[omsPolicy]` и `Core_Coverage.identifier[omsPolicy]` снята локальная обязательность `Identifier.type`, чтобы RuCore не требовал передавать тип полиса ОМС во всех случаях сверх базовой спецификации FHIR.
* При этом RuCore сохраняет две нормированные опциональные модели кодирования типа полиса ОМС: через HL7 `Identifier.type` и через справочник типов полисов ОМС НСИ МЗ РФ.
* Изменение приводит slicing-модель `omsPolicy` в соответствие с общим правилом RuCore: профиль задает, как оформлять данные при их использовании, но не навязывает лишние обязательные подэлементы без отдельного основания.

## Версия 0.8.0

Статус: draft

Ключевые изменения:

* Пересмотрено ограничение для `Core_Coverage.identifier[omsPolicy]` в части `type.coding`: RuCore больше не требует одновременно кодировать тип полиса ОМС через оба вложенных среза `hl7Type` и `omsType`.
* Срез `omsPolicy` по-прежнему задает нормированную форму идентификатора полиса ОМС, но downstream-руководства теперь не обязаны использовать сразу обе системы кодирования, если для их сценария достаточно одной.
* Изменение согласовано с общим принципом RuCore: наличие среза задает правила оформления данных при его использовании, но не должно без необходимости навязывать конкретную комбинацию вложенных представлений.

## Версия 0.7.0

Статус: draft

Ключевые изменения:

* Национальные терминологические привязки в базовых профилях RuCore ослаблены с `required` до `extensible`, чтобы использование российских справочников оставалось обязательным по смыслу, но отсутствие нужного кода не блокировало реализацию.
* Нормализованы канонические URI identifier system для `snils`, `identity-document` и `oms` во всех затронутых профилях.
* Добавлены `NamingSystem` для `identity-document`, `okpo` и `frmo`.
* Примеры ресурсов приведены к каноническим identifier system RuCore для основных идентификаторов, чтобы опубликованные образцы демонстрировали эталонную модель RuCore.
* Из профилей удалены явные тавтологии базовой FHIR-спецификации, которые не добавляли собственного контракта RuCore, включая повторные bindings для `Procedure.status` и `RelatedPerson.telecom.system`.
* Для идентификатора ФРМО введен отдельный URI identifier system `https://fhir.ru/ig/core/systems/frmo` вместо использования URI `CodeSystem` в `Organization.identifier.system`.

## Версия 0.6.0

Статус: draft

Ключевые изменения:

* Исправлены слишком узкие ограничения `Reference(... only ...)` в базовых процессных профилях RuCore с учетом базовой спецификации FHIR R5.
* В `Core_ServiceRequest`, `Core_DiagnosticReport`, `Core_Encounter`, `Core_Procedure` и `Core_CareTeam` возвращены все допустимые типы ссылок из R5, при этом для типов ресурсов, имеющих RuCore-профили, сохранено требование использовать именно профили RuCore.
* В `Core_Composition` снято некорректное сужение `subject`, чтобы не терять семантику `Reference(Any)` из R5, а для `author` и `attester.party` восстановлены все допустимые типы ссылок с использованием RuCore-профилей там, где они существуют.
* Обновлены связанные intro-страницы профилей, чтобы текстовая документация соответствовала новым ограничениям ссылок.

## Версия 0.5.0

Статус: draft

Ключевые изменения:

* Для `RelatedPerson.relationship` удалены локальный `CodeSystem` RuCore и связанные `ConceptMap`.
* Набор значений `relatedperson-relationship` переведен на использование кодов справочников НСИ МЗ РФ `1.2.643.5.1.13.13.99.2.14` и `1.2.643.5.1.13.13.11.1021`.
* Обновлены профиль `Core_RelatedPerson`, примеры и раздел 13 главы 5 ГОСТ-представления.
* Изменение внесено потому, что ведение отдельного справочника отношений не относится к ответственности группы разработчиков RuCore; практичнее опираться на существующие справочники НСИ МЗ РФ.

## Версия 0.4.2

Статус: draft

Ключевые изменения:

* На intro-странице `CodeSystem` `core-relatedperson-relationship` рядом с OID словарей НСИ МЗ РФ добавлены их наименования.
* В описаниях `ConceptMap` добавлены ссылки на соответствующие внешние справочники HL7 и НСИ МЗ РФ.
* В `ConceptMap` заполнены scope-поля, чтобы на опубликованных страницах не отображалась фраза `Mapping from (not specified) to (not specified)`.

## Версия 0.4.1

Статус: draft

Ключевые изменения:

* Для `CodeSystem` `core-relatedperson-relationship` добавлена intro-страница с навигационными ссылками на связанные `ConceptMap`.
* Улучшена видимость маппингов между каноническими отношениями RuCore, кодами HL7 и словарями НСИ МЗ РФ в опубликованном IG.

## Версия 0.4.0

Статус: draft

Ключевые изменения:

* Переработана терминологическая модель для `RelatedPerson.relationship`.
* Локальный `CodeSystem` `core-relatedperson-relationship` заменен на канонический набор понятий RuCore с собственными кодами.
* Добавлены явные `ConceptMap` для соответствия понятий RuCore кодам HL7 и словарям НСИ МЗ РФ `1.2.643.5.1.13.13.99.2.14`, `1.2.643.5.1.13.13.11.1021`, `1.2.643.5.1.13.13.99.2.240`.
* Обновлены `ValueSet`, профиль `Core_RelatedPerson` и примеры использования `RelatedPerson` в соответствии с новой канонической системой кодирования.
* В главе 5 ГОСТ-представления профилей добавлен сводный перечень используемых наборов значений с указанием опорных справочников и правил отбора элементов.

## Версия 0.3.0

Статус: draft

Ключевые изменения:

* Пересмотрена интерпретация профиля `Core_Address`.
* `Core_Address` рассматривается как профиль адреса на территории Российской Федерации, а не как универсальный национальный профиль любого адреса.
* Для адресов объектов, расположенных на территории Российской Федерации, применяется профиль `Core_Address`.
* Для адресов вне территории Российской Федерации применяется базовый тип данных `Address`.
* В профилях ресурсов внесена корректировка ограничений и пояснений, связанных с использованием `Core_Address`.

## Версия 0.2.0

Статус: baseline

Ключевые изменения:

* Сформирован исходный набор базовых профилей RuCore на основе FHIR R5.
* Определены базовые ресурсы, расширения, наборы значений и примеры для российского контекста использования.
