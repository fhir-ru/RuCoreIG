# Проект правил маппинга

Это подготовка алгоритма, а не выполненный маппинг конкретного XML. XPath, кратности и правила редакции 5 будут уточнены после чтения пакета.

## Формат таблицы результата

Каждая строка: стабильный ID правила; XPath с пространствами имен; значение/количество в примере; раздел руководства; ресурс и JSONPath назначения; преобразование; статус покрытия; связанный пробел.

Пространства имен определяются по XML. Основное CDA: `cda = urn:hl7-org:v3`; российские расширения нельзя считать CDA-элементами по одному local-name.

## Начальные направления

| Область CDA | Назначение FHIR | Что проверить на исходнике |
|---|---|---|
| `ClinicalDocument/id` | `Bundle.identifier` | Пара root/extension и семантика конкретной версии; `system=urn:oid:<root>` для OID |
| `ClinicalDocument/setId` | `Composition.identifier[misDocumentSet]` | Тип `mis-document-set`, OID `.50` |
| `ClinicalDocument/versionNumber` | `Composition.version` | Строковое представление номера, сохранение значения |
| Код, заголовок, дата документа | `Composition.type/title/date` | Нельзя подменять дату авторства временем сборки Bundle |
| Пациент | `Core_Patient`, `Composition.subject`, `Encounter.subject` | Идентификаторы и семантические типы, имя, пол, даты, адреса и контакты |
| Автор, подписант, хранитель | `Core_Practitioner`, `Core_PractitionerRole`, `Core_Organization`, `Composition.author/attester/custodian` | Различение личности и роли, `.70`, принадлежность организации, режим заверения |
| Случай | `Core_Encounter`, `Composition.encounter` | `.15`, `.17`, границы случая и посещения, даты; амбулаторную карту не смешивать с посещением без проверки |
| Источник оплаты | `Core_Coverage` и связь, выбранная по смыслу | В R5 использовать корректные beneficiary, insurer/paymentBy, kind; не выдумывать статус |
| Разделы документа | `Composition.section` | Код/заголовок/порядок, вложенность, CDA narrative → допустимый XHTML |
| Диагнозы | `Encounter.diagnosis` и при необходимости `Condition` | Две оси diagnosis.use, порядок, связь с текстом раздела; кардинальности R5 |
| Измерения и осмотр | `Observation` или narrative | Код, значение, единицы, время, интерпретация; не извлекать утверждения из текста без явного правила |
| Назначения | `ServiceRequest`, `MedicationRequest`, другие ресурсы по содержимому | Различить план, рекомендацию и выполненное действие |
| Отсутствующие значения | Механизм FHIR по типу элемента + отчет | `nullFlavor` не копируется строкой в значение; различать unknown, not applicable и отсутствие элемента |
| Технические сведения CDA | Паспорт/отчет или подходящий FHIR-элемент | typeId, templateId и версии справочников; не представлять CDA templateId как FHIR meta.profile |

## Сборка и проверка

Преобразователь должен принимать путь к XML и выдавать JSON Bundle плюс отчет прослеживаемости. Повторный запуск на одном источнике должен давать тот же результат, включая идентификаторы ссылок. Сгенерированные UUID можно получать детерминированно, но они не заменяют бизнес-идентификаторы.

Проверки: все ссылки разрешаются; первая запись — Composition; присутствуют system/value идентификатора и timestamp document Bundle; исходные идентификаторы и версии сохранены; narrative содержит исходное клиническое содержание; каждому исходному значению назначен статус. Затем отдельная проверка HL7 FHIR Validator R5 с применимыми профилями RuCore. Терминологические ошибки не подавляются ради зеленого результата.
