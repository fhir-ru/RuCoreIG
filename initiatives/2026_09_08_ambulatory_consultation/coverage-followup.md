# Уточнение Core_Coverage — 22.09.2026

По прямому поручению оператора согласованные изменения реализованы в исходниках Core_Coverage в текущей экспериментальной ветке. Это следующий этап после исходного маппинга; сохранённые отчёты эксперимента относятся к прежней базе 0.18.0 и не перезаписывались.

- Общий необязательный срез coverageDocument распознаётся по type с required-привязкой к НСИ документов оплаты.
- Вариант ОМС — вложенный срез coverageDocument/omsPolicy, использующий тот же дискриминатор по type и образец CodeableConcept с кодом ОМС.
- Номер документа и его система не сделаны обязательными. Для переданной системы номера ОМС сохранён URI RuCore.
- Вид полиса ОМС необязателен; при его наличии требуются система и код. Используется canonical URI справочника RuCore, согласованный с ValueSet.
- Полный пример содержит вид полиса, минимальный — только тип документа оплаты. Срезы кодирований указаны по имени; присваивание вида полиса целым Coding позволяет SUSHI 3.15.0 корректно обработать образец родительского CodeableConcept.
- Версия проекта изменена на 0.19.0 согласно политике содержательных изменений; история и метаданные синхронизированы.

Проверка ограничена локальным SUSHI по указанию оператора: 3.15.0, 0 Errors, 0 Warnings. Дополнительно просмотрены сгенерированный профиль, оба примера и версия ImplementationGuide. Полная FHIR-валидация на этом этапе не выполнялась; устранение ошибок исходного отчёта пока не заявляется.

Core_Patient, терминологические определения и ГОСТ не изменены. В ГОСТ остаётся прежнее описание Coverage (input/pagecontent/gost-06-resources.md, раздел Core_Coverage); его синхронизация отложена в рамках ранее установленного ограничения на изменения ГОСТ. Patient обсуждается отдельно. Публикация и push не выполнялись.
