# Исправление описания терминологий RuCore

Цель принята 22.09.2026: исправить недостоверные content CodeSystem, сначала зафиксировав опубликованный baseline, затем повторно опубликовать и сравнить QA. По прямому поручению оператора работа ведётся в main; все изменения сохраняются коммитами. Для отмены используется revert, без переписывания истории.

## Исходное состояние

В main fast-forward перенесены изменения до af7a7134dd29df9154d9de8703e8a3dde29fcff9 (RuCore 0.20.0), выполнен push. Полученная публикация проверена прямыми HTTP-запросами, без поискового кеша. Подтверждены версия, стабильность QA во время загрузки, точное совпадение differential профилей Patient/Coverage, состава/описаний всех CodeSystem и двух новых примеров Patient с generated из изолированного checkout исходного коммита. Publisher добавляет пустой корневой элемент differential; только это техническое добавление исключается при сопоставлении.

Baseline: **54 errors / 158 warnings / 89 information**, Publisher 2.3.4, SUSHI 3.20.1, терминологии HL7 7.4.0, extensions 5.3.0. Артефакты: [reports/baseline](reports/baseline), контрольные суммы и подтверждение содержимого — capture.json. Автобилдер не публикует SHA коммита, поэтому связь подтверждена содержимым и отсутствием следующего push до фиксации baseline.

Предшествующая опубликованная 0.18.0 сохранена в reports/preexisting для справки; она не используется вместо baseline. Разница preexisting-to-baseline включает уже выполненные изменения Patient/Coverage и изменение инструментов; не приписывается терминологической правке.

## Воспроизведение

```sh
bash run_sushi.sh
python3 scripts/check_terminology.py --self-test
python3 initiatives/2026_09_22_terminology/scripts/capture_ci.py REPORT_DIR --version VERSION --commit SOURCE_SHA --generated GENERATED_DIR
python3 initiatives/2026_09_22_terminology/scripts/compare_qa.py BASELINE_DIR AFTER_DIR --output COMPARISON_PATH
```

capture_ci не запускает сборку и отвергает старую версию/несовпадающее содержимое. compare_qa использует qa.xml (в qa.json только итоги), сохраняет кратность сообщений и описывает нормализацию. Сравнение не подменяет оценку причин новых ошибок.

## Проверка субагентами

- terminology_audit: независимый аудит всех15CS, реализация двух FSH-файлов, отдельная проверка Coverage реальным Validator.
- publisher_review: источники состояния autobuilder, границы привязки результата к SHA, риск required ValueSet-discriminator.
- qa_comparison: инструмент сравнения QA, проверка терминологической целостности, независимый review изменений.
